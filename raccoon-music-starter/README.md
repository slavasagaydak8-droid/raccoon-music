# RACCOON MUSIC — v0.2.0

Кроссплатформенный музыкальный плеер для Android и iPhone на React Native + Expo + TypeScript. Фирменный круглый логотип пользователя сохранён в `assets/raccoon-logo.png` и используется в шапке главного экрана. Другой персонаж вместо него не используется.

## Что добавлено в этом этапе

- SQLite-база `raccoon-music.db` с миграцией версии 1.
- Постоянная библиотека треков: название, исполнитель, URI сохранённой копии, исходный URI, имя файла, MIME-тип, размер, время изменения, длительность, альбом, обложка, избранное и дата импорта.
- Импорт одного или нескольких аудиофайлов через системный Document Picker.
- Копирование аудиофайлов в `Paths.document/audio`, чтобы ссылки не зависели от временного кэша.
- Избранное с сохранением в SQLite.
- Создание, переименование и удаление плейлистов.
- Добавление и удаление треков внутри плейлистов.
- Удаление трека из библиотеки удаляет его связи с плейлистами и пытается удалить сохранённую копию аудиофайла.
- Поиск по локальной библиотеке.
- Настройка `expo-audio` для фонового воспроизведения и lock-screen metadata.
- Сохранён премиальный чёрный стиль и оригинальный логотип енота.

## Требования

- Node.js **22.13.x или новее** (требование Expo SDK 58).
- npm.
- Для Android: Android Studio и Android SDK либо EAS Build.
- Для iOS: macOS и Xcode либо EAS Build.

## Установка

Извлеки архив, открой терминал в папке `raccoon-music-starter` и выполни:

```bash
npm install
npx expo install --fix
npx expo-doctor
npx tsc --noEmit
```

`expo install --fix` проверяет и выравнивает версии Expo-модулей под установленный SDK. В проекте целевой SDK 58: React Native 0.88 и React 19.3.

## Запуск на устройстве

Для Android:

```bash
npx expo run:android
```

Для iPhone (на Mac с Xcode):

```bash
npx expo run:ios
```

Для EAS development build dev client уже включён в зависимости проекта:

```bash
eas build --profile development -p android
# или
eas build --profile development -p ios
npx expo start --dev-client
```

После изменения `app.json` или native config plugins пересобери development build. Для проверки фонового аудио и native config plugins используй development build.

## Как проверить функции

1. Запусти приложение и открой **Моя музыка → Добавить музыку**.
2. Выбери несколько аудиофайлов. Проверь, что они появились в библиотеке и воспроизводятся.
3. Полностью закрой приложение и запусти снова: библиотека должна восстановиться из SQLite.
4. Нажми сердечко у трека, переключись на **Избранное**, перезапусти приложение и проверь сохранение.
5. Открой **Плейлисты**, создай подборку, переименуй её, добавь несколько треков и удали один из неё.
6. Перезапусти приложение и проверь, что плейлист и его состав сохранились.
7. Удали один трек из библиотеки: он должен исчезнуть из избранного и всех плейлистов; приложение также удалит свою копию файла, если ОС разрешит.
8. На физическом устройстве проверь фоновое воспроизведение, блокировку экрана, Bluetooth-наушники и системные прерывания.

## Известные ограничения этого этапа

- Встроенные ID3/Vorbis-теги пока не извлекаются. Сейчас сохраняются метаданные, которые отдаёт системный выборщик: имя файла, MIME-тип, размер и `lastModified`; название берётся из имени файла, исполнитель получает значение «Локальный файл». Длительность определяется плеером во время воспроизведения. Редактор тегов — отдельная следующая задача.
- Интернет-каталог пока не подключён. Никакие нелицензированные потоки и защищённые композиции в проект не встроены.
- Эквалайзер и обработка звука DSP пока не реализованы.
- Фоновое аудио и управление экраном блокировки настроены через `expo-audio`, но требуют проверки на реальных Android/iOS устройствах и release/development сборках.
- Список форматов, реально воспроизводимых, зависит от системного аудиодвижка Android/iOS.
- Нет облачной синхронизации: база и импортированные файлы хранятся локально на устройстве.

## Проверка качества

В этой среде исходники и конфигурация были проверены статически, а SQL-схема отдельно проверяется тестом на SQLite. Android/iOS native build, воспроизведение на реальном устройстве и `expo-doctor` требуют установки зависимостей и локальной среды разработчика; их успешный запуск здесь не заявляется.
